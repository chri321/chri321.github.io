Socket 编程接口详解

2024-12-25

Socket 通信流程

服务端先初始化 Socket，然后与端口绑定（bind），对端口进行监听（listen），调用 accept 阻塞，等待客户端连接。

客户端初始化一个 socket，然后连接服务器（connect），连接成功后发送数据请求。服务端接受请求并处理，然后回应数据到客户端，客户端读取数据，最后关闭连接，一次交互结束。

核心函数详解

1. socket()

  • protofamily：协议域（协议族）。常用值：

    • AF_INET — IPv4
    • AF_INET6 — IPv6
    • AF_LOCAL / AF_UNIX — Unix 域 socket
    • AF_ROUTE — 路由套接字

    协议族决定了 socket 的地址类型。如 AF_INET 使用 IPv4 地址（32 位）+ 端口号（16 位）的组合；AF_UNIX 使用一个绝对路径名作为地址。

  • type：socket 类型。常用值：

    • SOCK_STREAM — 流式套接字（TCP）
    • SOCK_DGRAM — 数据报套接字（UDP）
    • SOCK_RAW — 原始套接字
    • SOCK_PACKET — 数据包套接字
    • SOCK_SEQPACKET — 有序数据包套接字

  • protocol：指定协议。常用值：

    • IPPROTO_TCP — TCP 协议
    • IPPROTO_UDP — UDP 协议
    • IPPROTO_SCTP — SCTP 协议
    • IPPROTO_TIPC — TIPC 协议

  • 返回值 sockfd：socket 描述符（socket descriptor），唯一标识一个 socket，后续操作都通过它来进行读写。

2. bind()

  • sockfd：唯一标识一个 socket
  • addr：指向绑定 sockfd 的协议地址
  • addrlen：地址的长度

注意：服务器在启动时通常会绑定一个众所周知的地址（IP + 端口号），用于提供服务；而客户端不需要指定，由系统自动分配端口号和自身 IP 组合。这就是为什么服务器端在 listen 之前会调用 bind()，而客户端不会，而是在 connect() 时由系统随机生成。

3. listen() & accept()

  • listen()：将 socket 置为监听状态，等待客户端连接
  • accept()：从已完成连接队列中取出一个连接，返回一个新的 socket 描述符用于通信

4. connect()

客户端通过 connect() 向服务器发起连接请求。

Loopback（环回地址）

  • 地址 ::1 是 IPv6 的 loopback 地址，永远只代表”本机”
  • 在 IPv4 中，loopback 地址是 127.0.0.1

Loopback 接口用于测试网络应用程序，数据不会经过任何网络硬件，仅在主机内部处理。
