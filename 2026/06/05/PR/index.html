Git Pull Request 完整工作流指南

2026-06-05

本指南详细介绍了在 GitHub 上参与开源项目或团队协作时，从 Fork 仓库到提交 Pull Request (PR) 的完整标准工作流。

🛠️ 核心工作流步骤

1. Fork 仓库

在 GitHub 上打开目标开源仓库，点击页面右上角的 Fork 按钮，在个人账户下创建该仓库的完整副本。

5. 开发与提交

在功能分支上进行代码修改，然后分步提交：

💡 Commit Message 规范建议：

  • feat: — 新功能
  • fix: — Bug 修复
  • docs: — 文档更新
  • refactor: — 代码重构
  • style: — 代码风格调整（不影响功能）

6. 推送分支到远程

将本地功能分支推送到你的 Fork 仓库：

如果远程还没有该分支，Git 会提示设置上游跟踪：

7. 创建 Pull Request

  1. 在浏览器中打开你的 Fork 仓库
  2. GitHub 会自动检测到新推送的分支，显示 “Compare & pull request” 按钮
  3. 点击后填写 PR 信息：
    • 标题: 简明扼要地概括改动
    • 描述: 说明改动的目的、实现方式、测试结果等
  4. 确认 base 仓库（原仓库）和 compare 分支（你的分支）正确
  5. 点击 “Create pull request”

8. 代码审查与修改

提交 PR 后，维护者可能会提出修改意见：

💡 小技巧： 如果有多轮修改，可以使用 git commit --amend 来合并修改到上一个 commit（需要 git push --force）。

9. 合并 PR

PR 被批准后，维护者会将其合并到主分支。合并方式有三种：

方式效果适用场景
Merge Commit保留完整提交历史大型功能分支
Squash and Merge将所有 commit 压缩为一个小型改动、单次提交
Rebase and Merge线性历史，无 merge commit追求干净历史
