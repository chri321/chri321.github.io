TCP/IP 协议栈笔记

2023-06-06

TCP/IP 协议栈学习笔记，涵盖四层体系、核心协议、连接管理及应用层协议。

PART.1 TCP/IP 协议栈四层体系

1. 应用层

负责数据包在网络中的寻址和路由。常见协议有 HTTP（网页浏览）、FTP（文件传输）、SMTP（邮件发送）等。

2. 传输层

提供端到端的通信服务，确保数据的完整性和顺序。

  • TCP（Transmission Control Protocol）：提供可靠的、有序的和错误检测的数据传输服务。
  • UDP（User Datagram Protocol）：为应用程序发送和接收数据包，但不保证可靠性。

3. 网络层

主要协议是 IP（Internet Protocol）。特点是 IP 协议在网络中传输数据包，但不太可靠，可能会丢包。

4. 链路层

处理数据在本地网络中的传输。

  • 封装：发送数据时，每一层都会在数据包上添加自己的头部信息。
  • 分用：接收数据时，每一层都会移除自己的头部信息。
  • 常见技术有以太网（Ethernet）和 IEEE 802 标准。

5. ICMP（Internet Control Message Protocol）

IP 的附属协议，用于发送错误消息和操作信息。

OSI 七层模型与 TCP/IP 四层模型

OSI 七层模型

  1. 物理层：负责通过物理媒介传输原始的比特流。
  2. 数据链路层：提供节点间的数据帧传输和错误检测。
  3. 网络层：负责数据包的路由选择和转发。
  4. 传输层：提供端到端的通信服务，确保数据的完整性和顺序。
  5. 会话层：管理会话和连接，包括建立、管理和终止会话。
  6. 表示层：处理数据的表示、安全和压缩，确保一个系统的应用层所发送的信息可以被另一个系统的应用层读取。
  7. 应用层：为应用程序提供网络服务，如 HTTP、FTP、SMTP 等。

TCP/IP 四层模型

  1. 网络接口层：相当于 OSI 模型的物理层和数据链路层，负责与网络硬件的交互。
  2. 互联网层：对应 OSI 模型的网络层，负责路由和数据包的传输，主要协议是 IP。
  3. 传输层：对应 OSI 模型的传输层，提供端到端的通信服务，主要协议是 TCP 和 UDP。
  4. 应用层：对应 OSI 模型的会话层、表示层和应用层，为应用程序提供网络服务。

区别

  • 理论与实践：OSI 模型是理论模型，用于指导网络通信的标准化；TCP/IP 模型是实际应用模型，是互联网的基础。
  • 层数：OSI 模型更详细（七层），TCP/IP 模型更简化（四层）。

封装和分用过程

  • 封装：数据从应用层向下传递到链路层，每经过一层，该层都会在数据包上添加自己的头部信息。
  • 分用：数据从链路层向上传递到应用层，每经过一层，该层都会移除自己的头部信息。

端口号

用于识别同一 IP 地址上的不同服务或应用程序。

分类：

  • 知名端口号：预定义的端口号，用于常见网络服务（如 FTP 使用端口 21）。
  • 临时端口号：动态分配给客户端，用于建立通信，会话结束后释放。

分配范围：

  • 1024~4999：通常用于临时端口。
  • 大于 5000：通常为其他服务器预留，用于不太常见的服务或应用程序。

链路层

  • 以太网和 IEEE 802 封装。
  • 环回接口：
    • IP 地址：分配 IPv4（127.0.0.1）和 IPv6（::1）地址。
    • 数据包传输：发送到环回地址的数据包不会离开发送主机。
    • 测试和诊断：可用于测试网络应用程序。

环回接口要点：

  1. IP 地址：环回口通常被分配一个 IPv4 地址（127.0.0.1）和一个 IPv6 地址（::1），这些地址被称为环回地址。
  2. 数据包传输：发送到环回地址的数据包不会离开发送主机，而是在主机内部被处理。这意味着数据包在发送和接收过程中不会经过任何网络硬件。
  3. 测试和诊断：环回口可以用于测试网络应用程序是否能够正确地发送和接收数据包，而不需要实际的网络连接。

在操作系统中，环回口通常被实现为一个虚拟设备，如在 Linux 系统中的 lo（loopback）接口。这个接口可以在网络配置工具中看到，也可以通过命令行工具如 ifconfig 或 ip addr 来查看和管理。

MTU（最大传输单元）

  1. 定义：网络层数据包的最大尺寸，包括头部和数据。
  2. 以太网 MTU：标准为 1500 字节。
  3. IP MTU：理论上最大为 65535 字节，实际应用中通常小于此值。
  4. 分片：如果数据包超过 MTU，需要在网络中分片成更小的包。

IP 协议

IP 数据报格式

  • 4 位版本、4 位首部长度、8 位服务类型、16 位总长度等字段。
  • 3 位标志、13 位片偏移用于控制和标识分片。
  • 8 位生存时间（TTL）、8 位协议、16 位首部检验和等字段。
  • 32 位源 IP 地址和目的 IP 地址。
  • 可选的扩展选项字段。

特殊 IP

  • DHCP（动态主机配置协议）：自动为连接到网络的设备分配 IP 地址。

常用命令：

  • Windows 下：netstat
  • Linux 下：ifconfig

IP 首部字段详解：

  1. 4 位版本：表示 IP 协议的版本，IPv4 的值为 4。
  2. 4 位首部长度：表示 IP 首部的长度，以 32 位字（4 字节）为单位。IPv4 首部最小长度是 20 字节，此字段最小值是 5。
  3. 8 位服务类型（TOS）：用于指定数据报的优先级和服务质量要求。
  4. 16 位总长度（字节数）：表示整个 IP 数据报的长度，包括首部和数据，最大为 65535 字节。
  5. 3 位标志：用于控制和标识分片。DF（Don’t Fragment）位为 1 时表示不允许分片。
  6. 13 位片偏移：表示分片相对于原始数据报开始处的偏移量，用于数据报的重组。
  7. 16 位标识：用于唯一标识主机发送的每一份数据报，以便在接收端进行分片重组。
  8. 8 位生存时间（TTL）：限制数据报在网络中的寿命，防止数据报无限期地在网络上循环。
  9. 8 位协议：指定数据报携带的上层协议类型，如 TCP、UDP 等。
  10. 16 位首部检验和：用于检验首部的完整性。
  11. 32 位源 IP 地址：发送数据报的主机的 IP 地址。
  12. 32 位目的 IP 地址：接收数据报的主机的 IP 地址。
  13. 选项（可选）：用于提供额外的网络功能，如路由记录、时间戳等。如果首部长度超过 20 字节，通常就是因为包含了选项字段。
  14. 数据：IP 数据报中实际要传输的数据部分。

PART.2

ARP（地址解析协议）

ARP 是一种网络层协议，主要用于解析 IP 地址到对应的数据链路层地址（通常是 MAC 地址）的映射关系，负责将逻辑 IP 地址转换为物理 MAC 地址，确保数据能够在数据链路层正确传输。

  1. 地址解析
    • 当主机需要向另一个 IP 地址发送数据时，首先需要知道对应的 MAC 地址。
    • 主机会查询本地的 ARP 缓存，看是否已经有该 IP 地址对应的 MAC 地址。
    • 如果缓存中没有找到，主机会广播 ARP 请求数据包，询问目标 IP 地址对应的 MAC 地址。
    • 目标主机收到 ARP 请求后会回复 ARP 应答数据包，告知自己的 MAC 地址。
  2. 地址映射维护
    • 主机收到 ARP 应答后，会将 IP 地址和 MAC 地址的映射关系缓存下来，供后续使用。
    • 缓存条目会定期过期，需要主机主动更新。
  3. 地址冲突检测
    • 如果两台主机使用了相同的 IP 地址，ARP 协议可以检测到这种冲突。

ICMP（互联网控制报文协议）

ICMP 传递差错报文以及其他需要注意的信息。

  1. 错误报告
    • 当路由器或目标主机无法处理收到的 IP 数据包时，ICMP 会生成错误消息反馈给发送方，如”目标不可达”、”时间超时”等。
  2. 查询消息
    • ICMP 可以用于查询网络状态信息，如 Ping 命令就是使用 ICMP Echo 请求和响应实现的。
    • 还可以用于查询路由信息、主机配置等。

Ping

TCP/IP 实现在内核中直接支持 Ping 服务器。

Traceroute

它通过发送特殊的数据包（通常是 ICMP 或 UDP 数据包），显示数据包从源计算机到目标主机在 IP 网络中的路径。

IP 源站路由

是一种网络技术，它允许数据包的发送者指定数据包到达目的地的路径。

  1. 源路由选项：在 IP 头中包含一个选项，指定数据包必须经过的一系列中间节点。
  2. 严格与松散源路由：
    • 严格源路由：要求数据包严格按照指定的 IP 地址列表顺序转发。
    • 松散源路由：允许数据包在列表中的两个 IP 地址之间经过其他路由器。

PART.3 UDP

基本信息

  1. 面向数据报：UDP 是一个简单的面向数据报的运输层协议，在发送数据时不建立连接，直接发送独立封装的数据包。
  2. 输出操作：应用程序的每个输出操作都会生成一个 UDP 数据报，随后被封装在 IP 数据包中进行发送。
  3. 与 TCP 的区别：与面向流的 TCP 协议相比，UDP 不保证数据的顺序或可靠性。
  4. 不保证可靠性：UDP 不保证数据包能够到达目的地，只是将数据发送出去，不进行错误检查或重传。
  5. 数据报长度：应用程序需要关注 UDP 数据报的长度。如果超过网络的 MTU，数据报需要在发送前进行分片。

UDP 封装结构

  • IP 首部：20 字节
  • UDP 首部：8 字节
  • UDP 数据：可变长度

三大典型应用

  1. 查询类服务：如 DNS（域名系统），用于将域名转换为 IP 地址。
  2. 数据传输：如 TFTP（简单文件传输协议），用于在客户端和服务器之间传输文件。
  3. 流媒体：如语音和视频流，UDP 的低延迟特性使其适合实时数据传输。

UDP 的特点

  • 无连接：不需要建立和维护连接。
  • 速度快：由于没有建立连接的开销，UDP 通常比 TCP 更快。
  • 不保证顺序：数据包可能乱序到达。
  • 不保证交付：数据包可能丢失，不进行重传。
  • 无拥塞控制：不调整发送速率以避免网络拥塞。

适用场景

  • 需要快速传输且对数据丢失容忍度较高的应用。
  • 实时应用，如在线游戏、视频会议等，这些应用更看重传输速度而不是数据的完整性。
  • 广播或多播应用，如网络电视和广播。

广播和多播

三种 IP 地址类型

  1. 单播地址（Unicast Address）：用于点对点通信，每个单播地址对应网络上的一个唯一设备。
  2. 多播地址（Multicast Address）：用于一点对多点的通信，允许一个发送者发送数据包到多个订阅了该多播地址的接收者。
  3. 广播地址（Broadcast Address）：用于点对所有点的通信，用于将数据包发送到网络上的所有设备。

传输层协议支持

  • TCP：仅支持单播通信，提供可靠的、有序的和错误检查的数据传输。
  • UDP：支持单播、多播和广播，提供快速的数据传输，但不保证可靠性或顺序。

广播和多播的特点

  • 广播：
    • 数据包会被发送到网络上的所有设备。
    • 效率低，因为即使某些设备不需要这些数据，它们也会接收到广播包。
    • 消耗计算资源，因为每个设备都需要处理这些数据包。
  • 多播：
    • 数据包只发送给那些订阅了特定多播地址的接收者。
    • 比广播更有效，减少了不必要的数据传输。
    • 允许接收者动态加入或离开多播组。

PART.4 TCP

TCP 提供一种面向连接的、可靠的字节流服务。应用层数据被分割成 TCP 认为最合适的数据块。TCP 发送后启动定时器，等待目的端确认收到报文段，如果不能及时收到确认，将重发数据包。

主要字段

  1. 源端口号（Source Port）：表示发送端使用的端口号，用于标识数据的来源。
  2. 目的端口号（Destination Port）：表示接收端使用的端口号，用于标识数据的目的地。
  3. 序号（Sequence Number）：用于标识 TCP 数据流中的字节顺序，便于接收端按序重组数据。
  4. 确认号（Acknowledgment Number）：表示接收端期望收到的下一个字节序号，用于确认已成功接收的数据。
  5. 数据偏移（Data Offset）：指出 TCP 报文首部的长度，用于定位报文中数据部分的起始位置。
  6. 保留位（Reserved）：目前未使用，保留供将来扩展使用。
  7. 控制位（Flags）：包括 SYN、ACK、FIN 等标志位，用于标识报文的类型和 TCP 连接状态。
  8. 窗口大小（Window Size）：声明接收端的缓冲区大小，用于流量控制。
  9. 校验和（Checksum）：用于检测报文在传输过程中是否发生错误。
  10. 紧急指针（Urgent Pointer）：指出紧急数据的位置，用于支持带外数据传输。

TCP 的建立和终止

TCP 三次握手建立连接，四次挥手断开连接。

MSL（Maximum Segment Lifetime）

MSL 指的是一个 TCP 段在网络中可以存在的最大时间。2MSL 等待是指在 TCP 连接关闭过程中，主动关闭连接的一方在发送完最后一个 ACK 后，需要等待 2 倍 MSL 的时间，才会完全关闭连接。

  • 保证这次连接的重复数据段从网络中消失。
  • 确保 TCP 协议的全双工连接能够可靠关闭。
  • 防止新旧连接之间的混淆。

TCP 的交互数据流

Nagle 算法

一种用于 TCP 协议的流量控制技术，主要目的是减少网络中的小数据包数量，以提高网络传输的效率。

  1. 工作原理：当应用程序向 TCP 套接字发送小于 MTU 的数据包时，Nagle 算法会将这些数据包暂时存储在发送缓冲区中。
  2. 条件发送：当缓冲区中的数据达到 MTU 大小，或者收到相应的 ACK 确认，此时会将缓冲区中的所有数据一起发送。
  3. 优点：减少网络拥塞，提高吞吐量。
  4. 缺点：在某些情况下可能会引入不必要的延迟，尤其是在需要快速响应的交互式应用中。

TCP 的成块数据流

正常数据流：”隔一个报文段确认”，每次确认两个报文。

滑动窗口机制

滑动窗口机制是 TCP 协议中用于流量控制的关键技术。当发送方速率快于接收方时，它通过以下方式工作：

  1. 窗口大小通告：接收方根据自己的处理能力设定窗口大小，并通过 TCP 报文段通知发送方。
  2. 控制发送速率：发送方根据接收方通告的窗口大小来控制数据发送量，避免超出接收方的处理能力。
  3. 窗口滑动：发送方在收到接收方的确认后，会根据确认的序列号向前滑动窗口，以便发送新的数据包。
  4. 动态调整：接收方会根据缓冲区的使用情况动态调整窗口大小，并通过 ACK 报文段通知发送方。
  5. 提高效率：允许发送方在等待确认的同时继续发送数据，提高网络传输效率。
  6. 防止拥塞：在网络拥塞时，接收方减小窗口大小，降低发送方的数据发送速率，防止网络进一步拥塞。

左边沿移动到 ACK 确认序号的位置，右边沿移动到左边沿加上窗口的大小的位置。接收方不必在窗口填满才回复 ACK。

TCP 慢启动

  1. 问题背景：当发送方和接收方之间存在多个路由器和速率较慢的链路时，为了避免一开始就发送过多数据导致网络拥塞，采用了慢启动算法。
  2. 拥塞窗口（cwnd）：TCP 引入了另一个窗口机制——拥塞窗口。拥塞窗口是发送方用于流量控制的，而接收方使用的是通告窗口。
  3. 慢启动过程：
    • 拥塞窗口（cwnd）从一个较小的值开始，通常是 1 个 MSS（最大报文段大小）。
    • 每当收到一个 ACK，拥塞窗口就会加倍，呈指数增长。
    • 这种指数增长可以快速增加传输速率，直到达到一个特定的阈值。

TCP 慢启动是为了防止过多数据一开始就涌入网络，导致拥塞。它通过逐步增加拥塞窗口的方式，缓慢提高传输速率，直到达到一个合适的阈值。

PART.5 TCP 超时和重传

对于每个连接，TCP 管理 4 个不同的定时器：

  1. 重传定时器（Retransmission Timer）：用于在发送方等待数据包的确认（ACK）时计时。如果在超时时间内未收到 ACK，发送方会重传数据包。
  2. 坚持定时器（Persist Timer）：当发送方的窗口大小为零时，用于定期发送窗口探测（window probe）数据包，以检查接收方的窗口是否已经打开。
  3. 保活定时器（Keepalive Timer）：用于在长时间没有数据传输的情况下，定期发送保活消息，以检查连接是否仍然有效。
  4. 2MSL 定时器：测量连接处于 TIME_WAIT 状态的时间。

重传定时器的超时重传时间根据 RTT（Round-Trip Time） 值进行计算：

  1. RFC 793 计算方法：使用低通过滤器更新平滑的 RTT 值。
  2. Jacobson 1988 方法：改进的 RTT 估算算法。

PART.6 应用层协议

FTP 协议

数据传输主流协议。

两个信道：

  • 控制信道
  • 数据信道

两个模式：

  • 主动模式
  • 被动模式

HTTP 协议

  • 无状态：每个请求都是独立的，与之前的请求没有关联。
  • 基于文本：HTTP 使用文本（通常是 HTML）作为通信的数据格式。
  • 无连接：通信双方在交换完数据后，连接即被断开。
  • 简单处理：HTTP 服务器处理请求的方式相对简单。

常用 HTTP 方法：

  1. GET：请求指定的资源，应该只用于获取数据，不会产生副作用。
  2. POST：向指定的资源提交数据，通常用于创建新的资源或向服务器发送需要处理的数据。
  3. HEAD：与 GET 方法一样，请求指定的资源，但不返回消息体，主要用于获取资源的元数据。

SSL/TLS

用于在客户端和服务器之间建立加密链接。

  1. 加密技术：SSL 使用对称加密技术和非对称加密技术来保护信息安全。
  2. 身份验证：SSL 提供了对服务器和客户端的身份验证机制，确保数据的发送者和接收者是预期的实体。

HTTPS

基于 SSL 加密，HTTPS 工作在 443 端口，HTTP 默认在 TCP 80 端口。

SSL 握手过程：

  1. 客户端发送 ClientHello：客户端发送自己的证书信息，并请求服务器的证书。
  2. 服务器响应 ServerHello：服务器发送自己的证书信息，并交换加密密钥。
  3. 客户端验证服务器证书：验证服务器证书的合法性。
  4. 客户端发送 ClientKeyExchange：客户端生成随机密钥，并使用服务器公钥加密发送给服务器。
  5. 客户端发送 CertificateVerify：客户端使用私钥对前面发送的消息进行数字签名，以验证自己的身份。
  6. 协商加密算法：双方协商确定使用的加密算法和密钥。
  7. 加密通信：后续的应用数据都使用协商好的加密算法进行加密传输。
